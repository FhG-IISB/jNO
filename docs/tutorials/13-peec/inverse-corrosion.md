The first three tutorials run the model forwards — geometry in, circuit out. This one runs it
backwards. A busbar has corroded over a known stretch, the only measurable quantity is its terminal
resistance, and the question is how much metal is gone.

That is the shape every inverse problem has: a **parameter** nobody can see, a **measurement**
everybody can, and a forward model connecting them. It is cheap here because `jno.peec` is
differentiable end to end — the gradient of the measurement with respect to the unknown comes out of
the same solve that produced it. No finite differences, no second model, no adjoint to derive.

## The parameter lives in the problem statement

Exactly where a conductivity always has:

```python
loss_frac = jno.np.parameter((1,), name="loss_frac")
loss_frac.initialize(jax.nn.initializers.constant(0.2))    # a deliberately poor first guess
loss_frac.optimizer(optax.adam(0.03))

bar  = jno.Shape.box(...).attach(sigma=CU * (1.0 - loss_frac * corroded))
emag = jno.peec([v(*at("A")) - v(*at("B")) - 1.0], freq=0.0)
```

Because the material now carries a trainable parameter, **`emag.solve().R` is a trace node**, not a
number. So the objective is written the way every other jNO objective is written, and `jno.core`
threads the values:

```python
residual = ((emag.solve().R - R_measured) / R_measured) ** 2
crux = jno.core([residual], domain=jno.domain.from_array({"_": np.zeros((1, 1))}))
crux.solve(epochs=250)

recovered = crux.eval([loss_frac])
```

There is no `jax.grad` here, and no wrapper function. The parameter is part of the problem, which is
the same rule the geometry follows — what a region carries decides what it is.

## It recovers the answer

| | |
|---|---|
| healthy $R$ | 125.000 µΩ |
| measured $R$ | 189.039 µΩ (1.51×) |
| objective | 8.594e-02 → **2.232e-15** |
| **recovered** | **0.6500** against a truth of 0.65 — error 1.8e-07 |

!!! note "The measurement is synthetic, on purpose"
    It was generated by the same model at a known answer, which is what makes this a **test** rather
    than a demonstration: the recovered number has something to be wrong against. On real data the
    truth is exactly what you do not have.

## The same code on a field

One unknown from one measurement is a well-posed toy. The interesting case is a density per cell —
identical code, a parameter of a different shape — used here as a **design** variable rather than to
recover something:

```python
theta = jno.np.parameter((n_cells,), name="theta")
rho   = 0.5 * (1.0 + jno.np.tanh(theta))          # bounded in (0, 1) by construction
jno.core([busbar(CU * rho**3).solve().R * 1e6], domain=...).solve(epochs=40)
```

R falls from 1000 µΩ to 129 µΩ, approaching the 125 µΩ of solid copper.

!!! warning "Bound the density, or the bar beats the metal it is made of"
    That `tanh` is not cosmetic. Minimising resistance against an **unbounded** density walks
    straight past solid copper and reports a bar better than copper — the first version of this
    tutorial did exactly that, reaching 117 µΩ against a physical floor of 125 µΩ. Bounded, the
    optimum is *known*, so the answer can be checked rather than admired. A real topology
    optimisation adds a material budget on top, via `jno.le(...)` and a constrained optimiser.

## A limit worth knowing

A material may depend on a trainable parameter **or** on position, not both — a lattice conductivity
is one value per cell, and the cell centres are not in scope where the substitution happens. Give
the parameter the per-cell shape instead. `jno.peec` refuses the combination by name rather than
evaluating it somewhere arbitrary.
